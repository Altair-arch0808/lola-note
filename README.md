# Мой планер (React + Tailwind + Supabase)

Пастельный персональный планер, который работает и на вахте: график вахты в календаре, быстрая запись мыслей, экран «Сегодня», привычки и уходы, работа без интернета, установка на телефон как приложения.

Что внутри: экран «Сегодня», календарь с обратным отсчётом и графиком вахты, задачи (повторы, метки времени и места), «Входящие», ментальная карта (у каждого узла блокнот-тетрадь с карточками из ссылок и картинок), расписание день/неделя/месяц с drag-and-drop, журнал активности и аналитика, свой фон и обложки вкладок.

## Что нового в версии 2
- **График вахты.** Календарь → карточка «График вахты»: выберите, например, «30 через 30» или «60 через 30», укажите дату начала. Дни красятся («На вахте» — персиковый, «Дома» — мятный), первый день каждого периода помечен значком, считаются день периода и обратный отсчёт до отъезда или возвращения. Задачи и блоки расписания можно помечать «везде / на вахте / дома» и фильтровать; на экране «Сегодня» показывается то, что относится к текущему периоду.
- **Быстрая запись.** Поле «Что в голове?» на «Сегодня» и во «Входящих». Каждую запись потом разбираешь одним нажатием: **В задачу** (на сегодня), **В блокнот** (страница в категории «Заметки» на ментальной карте), **В идею** (страница в категории «Идеи»). Категории создаются сами при первом использовании. Если запись — просто ссылка, она станет карточкой.
- **Работа без интернета.** См. раздел ниже.
- **Сегодня.** Приветствие и статус вахты, быстрая запись, задачи на сегодня и просроченные (с кнопкой «завтра»), привычки и уходы с сериями дней, отметка настроения с лентой за неделю, ближайшее событие.

## Работа без интернета
- Сайт ставится как приложение (PWA). Первый раз откройте его **с интернетом** — приложение запомнится в телефоне.
  - Android (Chrome): меню ⋮ → «Установить приложение».
  - iPhone (Safari): «Поделиться» → «На экран Домой».
- Дальше всё открывается без сети. Записи, задачи, отметки, правки блокнота сохраняются на телефоне и **отправляются сами**, когда связь появится (при возвращении в приложение и раз в 20 секунд). В шапке появляется значок «Без сети · N в очереди» / «Ждут отправки: N».
- Чего офлайн нельзя: загружать картинки в Storage, входить в аккаунт впервые, видеть изменения с другого устройства.
- Не выходите из аккаунта, пока в шапке горит «в очереди» — при выходе неотправленное пропадёт (приложение предупредит).
- Если один и тот же элемент правили на двух устройствах без связи, побеждает то, что отправилось позже.

## 1. Supabase
1. Создайте проект на supabase.com.
2. **SQL Editor** → вставьте содержимое `schema.sql` → Run (создаст таблицы, защиту RLS и хранилище `media`).
   **Если база уже создана по прежней версии** — вместо этого один раз выполните `migration_v2.sql` (можно повторно). Делайте это **до** деплоя новой версии сайта, иначе создание задач и блоков выдаст ошибку.
3. **Project Settings → API** — скопируйте `Project URL` и `anon public key`.
4. (по желанию) **Authentication → Providers → Email** — отключите «Confirm email», чтобы входить сразу после регистрации.

### Данные привязаны к логину
Каждая строка хранит `user_id`, а Row Level Security в `schema.sql` не даёт видеть и менять чужое. Если база создавалась по очень старой версии схемы — один раз выполните `migration_user_isolation.sql` (там же подсказка, как закрепить старые записи за собой).

## 2. GitHub
Распакуйте архив, содержимое должно лежать в корне репозитория (рядом `package.json`, `render.yaml`, папка `public`):
```
git init && git add . && git commit -m "init"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

## 3. Render
- **New → Blueprint** и выберите репозиторий (подхватит `render.yaml`), либо **New → Static Site**:
  Build Command `npm install && npm run build`, Publish Directory `dist`.
- В Environment добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
- Deploy. Ключи подставляются при сборке — после их изменения нужен новый деплой.
- Сервис-воркер работает только на https (на Render так и есть) и только в собранной версии, не в `npm run dev`.

## Локально
```
cp .env.example .env   # впишите ключи
npm install && npm run dev
```

## Устройство офлайн-слоя (для разработчика)
- `store.js` — локальный кэш таблиц (localStorage) и очередь записей (outbox). `useTable` читает из кэша и пишет через очередь; id создаются на устройстве (uuid), поэтому строку можно менять и удалять до отправки. Правки одной строки в очереди склеиваются, «создал и удалил» до отправки не уходит на сервер.
- Сетевые ошибки оставляют операцию в очереди; ответ сервера с отказом (например, RLS) снимает операцию, откатывает строку и показывает сообщение.
- `public/sw.js` — кэш оболочки приложения и шрифтов; страница открывается из кэша, если сеть не отвечает 3 секунды.
- `shift.js` — расчёт периодов вахты; график хранится в `settings.shift`.
